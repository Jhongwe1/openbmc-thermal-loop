# 量測方法學（measurement）

> **這份文件決定我的圖能不能被挑戰。**
>
> 差別不在「我畫了圖」——AI 幫任何人都畫得出漂亮的圖。差別在於:
> 別人能不能拿我的原始資料、跑我的指令、得到同一張圖,
> 並且看得出我**沒有**在哪些地方偷懶或造假。
>
> 相關文件:[`plant-model.md`](plant-model.md)(被控對象是什麼)、
> [`env-baseline.md`](env-baseline.md)(在什麼東西上量的)。

## 1. 實驗協定 —— 每個實驗都必須寫齊七欄

| 欄位 | 說明 | 為什麼 |
|---|---|---|
| **假設** | 我預期看到什麼?**寫在跑之前** | 先跑再說「我本來就這樣想」是自我欺騙的標準流程 |
| **自變因** | 我只改了什麼?**必須只有一個** | 同時改兩個,那張圖什麼都證明不了 |
| **控制變因** | 什麼固定住了?seed、plant 參數、setpoint、負載曲線、swampd 版本 hash、映像檔完整檔名 | 「我以為只改了一個」是最容易錯也最容易被抓的一條 |
| **應變因** | 我量什麼?用 [`bench/metrics.py`](../bench/metrics.py) 的定義,不另外發明 | 指標定義只能有一份,否則 README 與圖會對不起來 |
| **重複次數** | **至少 5 個不同 seed,報中位數與範圍** | 跑一次然後截圖不是量測 |
| **原始數據路徑** | `bench/data/expNN_<variant>_seed<K>.csv` | 原始資料是證據,必須進 git |
| **產圖指令** | 一行,別人照打得到同一張圖 | 不能重現的圖等於沒有 |

### 1.1 ★「自變因只有一個」不是用寫的,是用檢查的

`bench/sim` 每次執行都會把**這次生效的完整參數**印到 stderr
(stdout 是純 CSV,不混在一起)。`bench/exp01_sysid.py` 收下五次執行的參數集,
逐項比對,**除了 `seed` 以外有任何一項不同就中止並報錯**。

```
控制變因檢查通過：5 次執行只有 seed 不同
```

> **為什麼要做到這一步:** 「我只改了一個變因」是實驗協定裡最容易講錯的一句話。
> 講錯的人通常不是想騙人,是**真的以為自己只改了一個**。
> 能讓機器檢查的事,就不要靠記憶。

## 2. 指標定義

**一個指標只在 [`bench/metrics.py`](../bench/metrics.py) 定義一次。**
README、履歷、圖上的標註、CI 斷言全部引用同一個來源。

目前已實作:`t_peak_c`(全程最高感測溫度)、`fan_power_rel`
(穩態 `(rpm/rpm_max)³` 的時間平均)。其餘標在該檔案的總表裡,註明哪一週實作。

> ### ⚠️ 2026-08-09:這份「唯一定義來源」曾經**一個測試都沒有**
>
> 對照組是**當時**的 C++ 那一側:26 個 gtest case、21 個被證明會咬人的 mutation
> (現在兩邊都長大了 —— 32 個 gtest case、24 個 pytest case、32 個 mutation)。
> Python 這一側只有 `ruff` —— 而 ruff 只查風格,不查算得對不對。
> **W7 的招牌宣稱 `recover_s_ratio` 就是這裡的函式算出來的**,
> 等它寫完再補測試等於讓數字先進 README、測試後到。
>
> 現在:`test/python/test_metrics.py`(接進 `meson test`)+ 7 個 Python mutation。
>
> **寫測試順手改掉的一個真隱患:** `fan_power_rel` 的「最後 120 秒」原本是
> **用列數**框的(取樣週期從**前兩列**推),所以
> ① 軌跡只要不是等間隔,視窗長度就錯,而且**不會有任何錯誤訊息**;
> ② 只有一列的軌跡會丟 `IndexError`,訊息看不出原因。
> 改成用時間框之後兩個都消失了 —— 而且**那本來就是這個指標的定義**
> (「最後 120 秒」講的是時間,不是列數)。
> L2 從 BMC 收資料時取樣間隔本來就會抖,這個陷阱留著就是留給 W9。

> **`fan_power_rel` 的物理依據 ——【查】風扇親和定律:**
> 系統阻抗不變時,風量 ∝ 轉速 N、靜壓 ∝ N²、**功率 ∝ N³**。
> 所以**轉速降 10%,功耗降約 27%**(1 − 0.9³ = 0.271)。
> ⚠️【判】它是**模型算出來的相對值,不是量到的瓦數**。
> 講的時候說「相對風扇功耗」,不要說「省了多少瓦」。

## 3. 誠實準則(七條)

違反任何一條,證據等級就從 T2 掉回 T4。

1. **沒量到的不要寫。** README 與履歷的每個數字都要指得到一個 CSV 與一張圖。
2. **不要挑最好看的那次跑。** 報中位數與範圍。
3. **不要把模擬講成實測。** 全文一致用「在我的熱模型上」,不要寫「在伺服器上」。
4. **不要外推。** 這是單節點集總參數模型,不能宣稱對多區域熱耦合有效。
5. **限制寫在圖旁邊**,不要只寫在 README 最後。**圖的 caption 就要寫「本圖為模擬結果」。**
6. **記錄版本。** 每張圖的 caption 要有映像檔完整檔名與**產生它的那份資料的 commit**。
7. **不要引用我沒查過的規格細節。**

### 3.1 圖的 caption 三要素

每張圖的 caption 一定含三樣東西:

```
<實驗說明:改了什麼、固定了什麼、幾個 seed、用什麼方法算的>
[Simulation on my own thermal plant - see docs/plant-model.md. Not measured on server hardware.]
image: obmc-phosphor-image-bletchley-20260728025045.static.mtd  |  data commit: <hash>
```

第三行由 [`bench/provenance.py`](../bench/provenance.py) 產生,**每張圖共用同一份實作**
(有測試守著:`test_every_figure_script_uses_the_shared_version_line`)。

> ### ★★ 2026-08-09:那串 hash 從「HEAD」改成「資料的 commit」
>
> **原本記的是產圖當下的 HEAD。那讓一句宣稱變成假的。**
>
> `bench/plot.py` 的 docstring 寫著「任何人 clone 下來執行同一行指令,
> 得到的是同一張圖」。實際上 **HEAD 每個 commit 都在變**,
> 所以同一份資料在不同時間畫出來**逐 byte 不同** —— 差的就是那串 hash。
> 而且 HEAD 常常與那張圖**無關**:修一個 typo 也會讓 caption 變。
>
> **這是真的去 clone 一份下來跑才發現的。**
> 那是這個專案唯一一個「別人會怎麼看到它」的檢查,而我做得太晚。
>
> 改成記「**這張圖的資料**最後一次變動的 commit」之後:
>
> | | 記 HEAD | 記資料的 commit |
> |---|---|---|
> | 資料沒動、隔了 10 個 commit 再畫 | ❌ 不同的檔案 | ✅ **逐 byte 相同** |
> | hash 指向什麼 | 一個可能無關的 commit | **產生這張圖的那一版資料** |
>
> 前置條件量過了:matplotlib 對同一份輸入是**決定性**的(連畫兩次逐 byte 相同)、
> PNG 裡**沒有時間戳**。所以「逐 byte 相同」是一個公平的要求,而不是奢望。
>
> **產圖程式碼刻意不算進那個 hash**(會有自我參照:改 `plot.py` 的那個 commit
> 在圖被畫出來的當下還不存在)。程式碼那一側由
> `test/python/test_figures.py` 守 ——
> **它會重畫一次,與 repo 裡那張逐 byte 比對**,
> 所以「改了產圖程式卻忘了重畫」會讓測試變紅。
>
> ⚠️ 資料有未 commit 的改動時,hash 後面會加 `-dirty`。

### 3.2 ★ 圖上的文字一律英文

不是崇洋。這台機器沒有 CJK 字型,而**就算裝了,「別人 clone 下來跑一次得到同一張圖」
就會依賴他們的字型設定** —— 沒裝的人會拿到一堆豆腐字。
**圖是交付物,交付物不能依賴我本機的環境。** 中文留在 `docs/` 與 `LOG.md`。

### 3.3 ★ 反造假設計清單(每張圖都要過)

| 檢查 | 為什麼 |
|---|---|
| 原始資料**不平滑、不取平均**畫上去 | 平滑過的曲線看不出是不是編的。**看得到雜訊才知道是量出來的** |
| 擬合曲線**疊在**原始資料上 | 分開畫兩張,讀者無法判斷擬合有多貼 |
| **所有重複全畫**,不是只畫最好看的那一條 | 誠實準則第 2 條 |
| **殘差要畫出來**,不是只報一個 RMS | 一個數字看不出「有沒有系統性偏差」 |
| y 軸的範圍要讓**雜訊與量化階梯看得見** | 見 §4.1 踩過的坑 |
| 擬合曲線**只畫在它有定義的區間** | 畫過頭會暗示模型預測了它其實沒描述的東西 |

### exp01 —— 開環系統識別(FOPDT)

| 欄位 | 內容 |
|---|---|
| **假設** | PWM 從 40% 階躍到 60% 後,感測溫度在 θ 秒後開始下降,以時間常數 τ 趨近新穩態。**K 必為負**。兩點法擬出的 τ 會略小於 `τ_die + τ_sense`、θ 會略大於設定的死區,因為 FOPDT 只有一個時間常數而模型有兩個一階環節;**可檢查的不變量是 τ + θ** |
| **自變因** | PWM(唯一) |
| **控制變因** | `power_w` 固定 150 W、`dt` = 0.1 s、階躍時刻 300 s、總長 900 s、plant 參數全部使用預設值。**由程式檢查**(§1.1) |
| **應變因** | 感測溫度序列 → 兩點法算出的 K / τ / θ / 擬合殘差 RMS |
| **重複次數** | 5 個 seed(0~4),報中位數與 min~max |
| **原始數據** | `bench/data/exp01_sysid_seed{0..4}.csv`(各約 500 KB,已進 git) |
| **中繼資料** | `bench/data/exp01_sysid_meta.txt`(含 sim 回報的完整生效參數) |
| **擬合結果** | `bench/data/exp01_fit.txt`(每個 seed 的值 + 中位數 + 範圍) |
| **圖** | `figures/fig1_sysid.png` |
| **重跑** | `python bench/exp01_sysid.py --out bench/data && python bench/plot.py --fig 1` |

**結果(2026-08-07 實測,5 個 seed 的中位數,方括號是 min~max):**

| 量 | 中位數 | 範圍 | 模型設定值 |
|---|---:|---|---|
| **K** | **−0.3147 °C/%PWM** | [−0.3151, −0.3144] | — |
| **τ** | **43.97 s** | [40.25, 44.45] | `τ_die` = 45 |
| **θ** | **7.20 s** | [6.58, 8.84] | `deadTime` = 3 |
| 擬合殘差 RMS | 0.060 °C | [0.056, 0.089] | — |
| **τ + θ** | **50.99 s** | [49.09, 51.59] | `τ_die + τ_sense + θ` = **51.0** |

**兩個交叉驗證(這一段才是這個實驗的價值所在):**

1. **`τ + θ` 守恆。** 單看 τ 會覺得「怎麼比 48 小」,單看 θ 會覺得「怎麼比 3 大」,
   但**兩個一階環節串聯用 FOPDT 擬合,感測器那一段遲滯會被算進 θ 裡**,總和才是不變量。
   實測 50.99 vs 理論 51.0,差 0.02%。
   → **這是「識別方法對不對」的檢驗,而不是「模型對不對」的檢驗。**
     真實系統上我永遠不知道正確答案,所以要先在知道答案的系統上驗方法。
     這一條也有 gtest:`Identify.RecoversKnownTimeConstants`。
2. **殘差落在雜訊底上。** 量測雜訊 σ = 0.05 °C,量化的 RMS 是
   `LSB/√12 = 0.0625/3.464 = 0.018 °C`,兩者獨立所以平方相加開根號 = **0.053 °C**。
   實測殘差 0.056~0.060。
   → **殘差幾乎等於雜訊底,代表 FOPDT 這個形狀沒有留下系統性偏差。**
     剩下那約 0.028 °C 的系統性成分,對 6.35 °C 的總變化量而言是 0.4%。

**已知限制:**

- seed 2 是離群值(τ = 40.25、θ = 8.84、殘差 0.089),範圍的寬度幾乎由它一個決定。
  **照協定報中位數與範圍,不剔除它。** 剔除離群值需要事先定好規則,事後剔除就是挑資料。
- 這是**開環**實驗,量的是被控對象本身,與控制器無關。

### 4.1 ⚠️ Fig 1 第一版踩到的坑

第一版把整段 0~900 s 都畫上去,結果 **0~240 s 那段從 25 °C 爬到 61 °C 的冷機暖機
把 y 軸拉大了五倍**,真正的實驗(6.35 °C 的變化)被壓在圖的上緣。後果是:
**雜訊完全看不見、量化階梯完全看不見、死區只剩一條線** ——
而「看得到雜訊」正是 §3.3 的第一條反造假要求。

定稿的做法:
- x 軸從階躍前 60 s 開始(`t = 240 s`),**並在 caption 明講被略過的是什麼、為什麼**,
  原始 CSV 仍然是完整的 0~900 s。
- 加一個**死區放大鏡**(階躍前後 50 s 的 inset),讓 θ 變成一段看得見的平台。
- 加一個**殘差面板**,讓「有沒有系統性偏差」用眼睛就看得出來。

> **教訓:** 反造假設計不是加註解,是**版面決定**。
> 一張把資料壓成一條線的圖,再誠實的 caption 也救不回來。

### exp02 —— 兩點符號檢查(W5)

| 欄位 | 內容 |
|---|---|
| **假設** | `ec::pid()` 的誤差是 `setpoint − input`。input 是**絕對溫度**時,溫度上升會讓 error 變負,所以要讓風扇需求隨溫度上升,`proportionalCoeff` **必須是負的**。這句話是**從原始碼推出來的,不是量出來的** —— 所以要量。**預期:** `Kp = +500` 時「越熱輸出越低」,`Kp = −500` 時「越熱輸出越高」 |
| **自變因** | `die0` PID 的 `proportionalCoeff`(唯一)。**由程式改設定檔,不手動編輯**,而且 `assert n == 1` 確認只改到一個欄位 |
| **控制變因** | setpoint 65 °C、`outLim` [3000, 15000]、`samplePeriod` 1.0 s、兩個溫度點 55 / 75 °C、每點沉澱 10 s、映像 `…20260728025045`、swampd `0.1+git0+c5e59550d3-r1`、BMC 不重開。**★ 完整生效設定原樣存進 meta 檔** —— 兩份 meta `diff` 起來**只有 `kp=` 與 `proportionalCoeff` 兩行不同**,這就是「單一變因」的機器可驗證版本 |
| **應變因** | `/tmp/pidlog/pidcore.die0` 的 `input` / `error` / `proportionalTerm` / 未箝位輸出 / 箝位後輸出 |
| **重複次數** | **5 次**。⚠️ 這條路徑是**數位、決定性**的,所以報的不是中位數與範圍,是「**5 次逐點完全相同**」—— 那比一個中位數更強。腳本自己會檢查,不同就以非零離開碼失敗 |
| **原始數據** | `bench/data/exp02_signcheck/kp{500,-500}.csv` + 各自的 `*_meta.txt` |
| **重跑** | `./tools/sign_check.sh 500` / `./tools/sign_check.sh -500`(跑完**自動還原** BMC 為 baseline 並驗證 swampd 回到 active) |

**結果(2026-08-09 實測,5 次重複完全相同):**

| Kp | 55 °C(低於 setpoint) | 75 °C(高於 setpoint) | 判讀 |
|---|---:|---:|---|
| **+500** | **5031** | **3000** | ❌ 越熱轉越慢 —— 符號錯 |
| **−500** | 3000 | **4969** | ✅ 越熱轉越快 —— 符號對 |

> **★ 這個實驗真正的收穫不是「符號要負的」,是那兩個 3000。**
> 兩組**都有一個點停在 3000** —— 因為被 `outLim_min` 箝住了。
> **只看單一個溫度點,兩種符號分不出來。**
> 症狀不是「風扇變慢」,是「**風扇卡在最低速,而且看起來一切正常**」。
> 這也是為什麼係數用 ±500 而不是計畫寫的 ±100:
> Kp=100 時 |輸出| 只有 1000,**兩個點都會被箝到 3000,實驗會成功地什麼都沒測到。**

> ⚠️ **`input_c` 是 54.938 / 74.938,不是 55 / 75。** 那一格差是注入路徑的

### exp04 —— 注入路徑的傳遞特性(2026-08-09)

| 欄位 | 內容 |
|---|---|
| **假設** | **寫在跑之前:** ① 讀值只落在間距約 62.5 m°C 的離散階上;② **正好落在格點上的要求值會低整整一格** —— 理由是 QEMU setter 的 `(temp*256−128)/1000` 加上 C 的往 0 截斷。**純量化器不會有 ②**;③ 讀值有快取,注入後立刻讀會拿到上一個值 |
| **自變因** | 注入的溫度(唯一) |
| **控制變因** | 同一顆晶片 i2c-0 0x4f 通道 0、同一份映像、QEMU 11.0.1、kernel `6.18.40-c2b9fc3`、BMC 不重開、期間不跑其他實驗(全部記在 `meta.txt`) |
| **應變因** | BMC `temp1_input`(m°C)、QMP 讀回值(m°C)、**注入到可見的延遲**(ms) |
| **重複次數** | grid 掃描 **5 次**,報「5 次逐點完全相同」;延遲量測 **6 次轉換** |
| **原始數據** | `bench/data/exp04_injection/{grid,sweep,latency}.csv` + `meta.txt` |
| **重跑** | `python bench/exp04_injection.py`(需要 BMC)。**驗證不需要 BMC:`python bench/exp04_injection.py --check`** |

**結果:**

| 量 | 值 | 證據 |
|---|---|---|
| **LSB** | **0.0625 °C** | 細掃出 **7 個相異階**,階距 62/63 m°C(62.5 不是整數) |
| **注入偏壓** | **−62 m°C = 整整一個 LSB** | 7 個格點 × 5 次重複 = **35 個觀測,零例外** |
| **預測式命中率** | **68/68,零誤差** | 三段轉換算式,見 [`plant-model.md` §2.1](plant-model.md) |
| **注入到可見延遲** | 中位數 **351 ms**(範圍 178~423) | 6 次轉換、25 ms 取樣;與 driver 的 `HZ/2` = 500 ms 快取窗口一致 |

> **★★ 這個實驗的方法學重點(面試會問):**
> `--verify` 是「輪詢到讀值等於**我的預測值**為止」。那個機制當**閘門**很好,
> 拿來**產生這裡的資料就會變成同義反覆** —— 我等到它等於我的預測,
> 然後宣稱它等於我的預測。
> 所以量測用的是**穩定性判定**(連續數次讀到同值、橫跨兩個快取窗口),
> **那條判定與預測值完全無關**;預測只在事後當成一欄放進 CSV。

> **★★ 另一課:量測工具比現象慢,會量出「現象不存在」。**
> 第一版每讀一次開一條新 ssh(約 0.4 s),與 0.5 s 的快取窗口同一個量級,
> 於是自我檢查回報「快取不存在」。改成一條持久連線(毫秒等級)才量得出延遲。
